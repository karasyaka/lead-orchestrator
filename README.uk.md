# Lead Orchestrator

Lead Orchestrator допомагає розробнику або власнику проєкту вести одну задачу через Codex, Claude Code та Antigravity. Він допомагає розподілити роботу, передати потрібні пояснення та перевірити результат. Працює через інструменти, які вже налаштовані й доступні у вашому середовищі.

Використовуйте його для багатокрокової задачі, передачі роботи або задачі з межами, які наступний агент має зберегти. Для простої самодостатньої правки такий процес зазвичай не потрібен.

## Чим допомагає

- Тримати в полі зору мету, погодження та сторонню незавершену роботу.
- Розподілити задачу між доступними й дозволеними інструментами, не втративши потрібні пояснення.
- Перевірити повернений результат і показати, що пройшло, не пройшло або не запускалося.

[Переглянути кейс проєкту](https://hrybachov.com/uk/cases/lead-orchestrator): задача, межі реалізації та поточні обмеження.

## Практичний приклад

У репозиторії вже є стороння незавершена робота, а вам треба підготувати реліз. Якщо інструменти доступні й дозволені, Codex веде задачу, Claude Code перевіряє конкретний документ, а Antigravity перевіряє вигляд сторінки. У кожній передачі є мета, дозволені файли, докази й умова зупинки, тому результат можна перевірити без повторення всієї задачі. «Лише план» і «без деплою» лишаються обмеженнями: координація не дає дозволу змінювати production.

## Швидкий старт

Використовуйте цей пакет як єдине джерело змін. Встановіть його в одну папку `lead-orchestrator` для свого середовища, потім викличте в новому або наявному чаті.

### Codex

Поточна документація Codex використовує особисту папку `~/.agents/skills/lead-orchestrator/` або репозиторну `.agents/skills/lead-orchestrator/`. На цьому хості раніше тестувався старий шлях `~/.codex/skills/lead-orchestrator/`. Перед вибором перевірте документацію вашого хоста та наявні інсталяції.

Скопіюйте ці файли зі збереженням структури:

```text
SKILL.md
agents/openai.yaml
```

Для особистої інсталяції:

```text
~/.agents/skills/lead-orchestrator/SKILL.md
~/.agents/skills/lead-orchestrator/agents/openai.yaml
```

Для репозиторної інсталяції використовуйте `.agents/skills/lead-orchestrator/` з такою самою структурою. Не ставте одну версію водночас у старий і поточний шлях Codex, якщо свідомо не підтримуєте обидві копії: автоматичної міграції чи синхронізації немає.

У новому або наявному чаті:

```text
Застосуй $lead-orchestrator і продовжуй цю задачу в погоджених межах.
```

## Приклади запитів і форма відповіді

Дайте коротку інструкцію з межею, яку треба зберегти. У відповіді мають бути простою мовою відновлена мета, межі, докази та можливий блокер; точне формулювання залежить від хоста і задачі.

План без редагувань:

```text
Застосуй $lead-orchestrator і склади лише план цього релізу. Не редагуй файли й не деплой.
```

Очікувана форма: запропоновані межі, наступні перевірки без змін, суттєві ризики та відсутність редагувань або деплою.

Перевага для придатного виконавця:

```text
Застосуй $lead-orchestrator і продовжуй цю задачу. Для придатної делегованої роботи переважно обирай Claude.
```

Очікувана форма: задача триває в межах наявних дозволів; придатна делегована задача може врахувати цю перевагу, а відхилення пояснюється.

Лише один виконавець або повернення до автоматичного вибору:

```text
Для делегованої роботи в цій задачі використовуй тільки Claude.
Поверни автоматичний вибір для цієї задачі.
```

Очікувана форма: `тільки` зупиняє залежну делеговану роботу, якщо вказаний виконавець не може її виконати; `автоматично` прибирає цю перевагу для майбутніх призначень. Жодна з інструкцій не додає дозволів хоста й не перезапускає вже запущену роботу.

Якщо в уже відкритому чаті список скілів не оновився, попросіть агента прочитати встановлений `SKILL.md` за повним шляхом. Це ручне читання, а не доказ штатного виклику `$lead-orchestrator`.

[Документація скілів Codex](https://learn.chatgpt.com/docs/build-skills)

### Claude Code

Для особистого скіла скопіюйте `SKILL.md` до:

```text
~/.claude/skills/lead-orchestrator/SKILL.md
```

Для скіла в проєкті використовуйте точний шлях:

```text
.claude/skills/lead-orchestrator/SKILL.md
```

`agents/openai.yaml` для Claude Code не потрібен.

У новому або наявному чаті Claude Code:

```text
/lead-orchestrator Продовжуй поточну задачу в погоджених межах.
```

[Документація скілів Claude Code](https://code.claude.com/docs/en/skills)

### Antigravity CLI

Скопіюйте `SKILL.md` без змін до вкладеної структури, перевіреної на цьому хості:

```text
~/.gemini/antigravity-cli/skills/lead-orchestrator/SKILL.md
```

Документація Antigravity описує пласку структуру, а в зафіксованому локальному тесті працювала вкладена структура вище. У своєму середовищі перевірте виявлення через `/skills`, потім викличте `/lead-orchestrator` у новій або наявній сесії. Для IDE шляхи можуть відрізнятися.

[Документація плагінів Antigravity CLI](https://antigravity.google/docs/cli/plugins/)

## Вибір виконавця

Перевагу можна сформулювати звичайною мовою:

```text
Для цієї задачі переважно делегуй Claude придатну роботу.
Для делегованої роботи використовуй тільки Claude.
Поверни автоматичний вибір для цієї задачі.
```

`переважно` обирає вказаного виконавця, коли це доречно й дозволено, та пояснює відхилення. `тільки` зупиняє залежну роботу, якщо цей виконавець не може виконати задачу або обов'язкове рев’ю. `автоматично` повертає звичайний вибір середовища. Перевага діє для задачі, якщо її прямо не поширили на поточний чат; вона не перезапускає вже запущену роботу й не переноситься в інший чат. Повідомлені відсотки ліміту — неперевірений орієнтир, а не баланс, дозвіл змінювати вибір чи обіцянка нульових витрат ліда. Переваги не надають нових інструментів, дозволів, доступу до акаунтів чи запуску провайдера.

## Безпечне оновлення та видалення

Перед оновленням визначте й перегляньте точну встановлену папку `lead-orchestrator`. Замінюйте лише файли в цій папці з цього джерела, зберігаючи структуру середовища. Для Codex після копіювання звірте з оригіналом і `SKILL.md`, і `agents/openai.yaml`.

Для видалення приберіть лише визначену папку `lead-orchestrator`. Не видаляйте батьківську папку `skills`. Видалення не стирає інструкції, уже прочитані активним чатом: попросіть його вийти з режиму ліда.

## Сумісність і межі

- Скіл залежить від інструментів, дозволів, інструкцій та можливостей виконавців конкретного хоста. Власних пакетів чи сервера він не потребує.
- Історичні докази охоплюють передавання TXT і зображень у Codex, а також TXT/PDF і зображень у Claude. Це не доводить універсальну сумісність хостів.
- Візуальний доступ не доводить точності читання. Розпізнавання тексту на зображенні може помилятися; важливі числа звіряйте з першоджерелом.
- DOCX, XLSX, аудіо та відео не тестувались і лишаються залежними від хоста.
- Зафіксований збій Antigravity у фоновому записі залишає обмеження для зачеплених фонових записів, доки його не виправлять і незалежно не перевірять. Це не глобальна заборона провайдера.
- Скіл не переносить між хостами історію чату, облікові дані, доступ до файлів або дозволи.

## Приватність і вирішення проблем

Lead Orchestrator сам не збирає телеметрію та не створює постійну пам'ять. Він працює лише з контекстом та інструментами, які вже надає ваш хост. Перед передаванням агенту чутливих матеріалів перевірте політику даних хоста й правила проєкту.

| Симптом | Що перевірити |
| --- | --- |
| Скіл не видно у списку | Перевірте шлях для конкретного хоста та оновіть виявлення. У наявному чаті ручне читання файлу — окремий запасний варіант. |
| Агент почав редагування після «лише план» | Зупиніть задачу й повторіть межу. Зафіксуйте відтворювану проблему, якщо явні межі або погодження не збережено. |
| Перевагу виконавця не можна виконати | `переважно` може обрати придатну дозволену альтернативу; `тільки` має зупинити залежну роботу й пояснити причину. |
| Важливе число на зображенні | Звірте його з першоджерелом: передавання або скриншот не доводять точності розпізнавання тексту. |
| Є фоновий запис Antigravity | Не запускайте зачеплений запис без нагляду, доки поведінку не виправлять і не перевірять незалежно. |
